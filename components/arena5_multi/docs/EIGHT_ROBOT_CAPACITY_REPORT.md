# 八机器人容量压测报告

运行目录：`logs/runs/20260924_172732_eight_robots_capacity_gpu3`  
测试时长：600 秒墙钟时间  
结论：达到容量边界，正式支持规模保持为 4 台。

## 观测结果

| 指标 | 八机结果 | 四机正式结果 |
|---|---:|---:|
| RTF | `0.1201` | `0.2386`（30 分钟） |
| 雷达仿真频率 | 每台约 `10 Hz` | 每台约 `10 Hz` |
| 雷达墙钟频率 | 每台约 `1.201 Hz` | 每台约 `2.386 Hz` |
| RSS 均值 / 最大值 | `13547.6 / 13548.3 MiB` | `9221.9 / 9223.3 MiB` |
| GPU 显存均值 / 最大值 | `3860.8 / 3861 MiB` | `3562 / 3562 MiB` |
| CPU 均值 / 最大值 | `749.3% / 3186%` | `784.4% / 1611.2%` |
| 线程均值 / 最大值 | `2562 / 2562` | `1676.1 / 1680` |
| TF、odom、joint state | 8 台均存在 | 4 台均通过 |
| NavigateToPose | 仅 `robot_1` 就绪 | 4 台均就绪 |

8 台的雷达消息仍保持仿真时间 10 Hz，但 RTF 降低使墙钟接收间隔约为 0.83 秒，超过首版守护
阈值。8 台均报告 `lidar_stale` 与 `lidar_stamp_stale`，机器人 2–8 的 Nav2 生命周期未完成
激活。因此本结果只证明同一 Isaac 世界可生成并持续发布 8 台基础状态，不能用于 8 台导航或
安全性能声明。

用户在 2026-09-24 明确允许临时降低八机验收标准以加快收敛。本版据此停止继续调参，把八机
固定为可重复容量压测配置；正式验收和对外支持上限仍为 4 台。后续若要求 8 台导航，应先分析
渲染传感器负载、Nav2 启动并发、DDS 线程数与守护时限，且需重新完成完整验收。
