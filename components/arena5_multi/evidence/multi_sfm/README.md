# Multi-SFM 验收记录

最终是否通过以 `acceptance.json` 及其中列出的报告哈希为准；本轮列出的十项验收均已通过。源码绑定范围为 Git 跟踪的 `src/`、`scripts/`、`config/`。

认证范围为两台机器人、1/6 名普通行人、机器人最高 0.26 m/s 和 1.0 rad/s、NoOp 心理模型、20 Hz Isaac 物理/渲染、40 Hz 社会力积分。旧 HuNav 六行为保持独立后端。

验收包含固定种子 CPU 轨迹矩阵、真实 ROS 节点故障注入、GPU 角色实际位姿与里程计时间对齐、双机运动交互、十轮双机导航、三十分钟持续运行及旧六行为回归。实际角色位姿来自 Character Graph，不使用请求位姿充当测量值。

局部地图清除测试仅对自由栅格射线覆盖的旧占据格及其膨胀邻域计时，上限为 2 个仿真秒。没有充分自由射线覆盖的邻域另计，不能据此宣称整个旧轨迹区域已清空。

`diagnostics/` 保存开发过程中失败的测试，不能作为发布通过证据：

- 原长测记录过雷达超时和 `robot_stamp_stale` 锁存，后续增加数值边界回归与具体时间差诊断。
- 初版实际角色/雷达使用 `World.current_time`，与 `/clock` 存在固定偏移；新模式已统一 Graph 时基。
- 时基修复后，显示服务仍受每帧一次 ROS 回调处理限制而积压；新模式使用每帧最多八次就绪回调处理和最高 10 Hz 串行显示更新。

社会力模型不构成任意密度、速度和场景下的无碰撞保证；本次未实现 SIR/SEIR 传播方程，也未验证四机、高速、复杂非矩形场地或心理模型的行为学有效性。

## 最终结果

- 38 项 Python 测试、9 项 C++ 测试、120 组固定种子轨迹、5 类故障注入通过。
- 一人/六人双机运动的最小净距分别为 0.289/0.272 m；最大显示误差为 0.028/0.019 m。
- 最终六人场景中，两台机器人各完成 10 个导航目标。
- 30 分钟长测检查 19,723 个实际位姿样本，无跳过样本或故障；最大显示误差 0.039 m，平均实时因子约 0.548。
- 有充分自由射线覆盖的清除样本最大延迟约 0.1 个仿真秒；未覆盖邻域另计。
- 原共享 underlay 的六行为验证通过，特殊行为响应类型 3、4、5、6 均观测到。

完整数值与最坏误差时刻见对应 JSON；`six_resources.json` 为运行负载采样，不构成其他机器的性能保证。
